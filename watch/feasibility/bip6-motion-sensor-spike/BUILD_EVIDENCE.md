## Tool/security observations

- The app declares only the Zepp accelerometer and gyroscope permissions. It
  declares no background-service, storage, BLE, network, or notification
  permission.
- The page requests one finite 150-second screen-lighting interval through
  `@zos/display`, then explicitly resets it on normal page destruction and on
  a caught synchronous page-build failure. The display-lifetime adapter
  contains API failures and makes cleanup idempotent. This changes neither the
  permission set nor the foreground-only acquisition boundary.
- The self-test schedules its stop path using a nominal 1,000 ms timer delay.
  A successful stop is not repeated. If the first stop request throws, cleanup
  permits one further attempt and no more; stale timer callbacks are ignored.
  This is not evidence of a 1,000 ms execution deadline or physical duration.
- Timing observation uses a fixed set of scalar fields per stream and retains
  no callback history, paired samples, raw-motion log, or algorithm input
  buffer.
- There are no delivered npm runtime dependencies; npm packages are used by
  the development build only.
- The clean development dependency install reported 31 known transitive
  vulnerabilities: 3 low, 7 moderate, 19 high, and 2 critical.
- Zeus CLI 1.9.3 still needs the checked compatibility link to its bundled
  `zeppos-app-utils`. Zeus and its dependency tree require NPS/security
  evaluation before build output is accepted as controlled lifecycle evidence.
