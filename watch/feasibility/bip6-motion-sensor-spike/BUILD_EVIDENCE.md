**Controlled work item:** DOC#5

**Scope:** Non-clinical foreground ACC/GYRO acquisition, bounded callback
timing observations, finite page-bright lifetime, and alert UI self-test

## Static and unit verification

- Node.js syntax checks passed for the app, page, and all three shared
  libraries.
- `npm test` completed with exit code 0.
- Twenty-four named checks in three test files passed. Seventeen checks cover
  vector conversion,
  invalid data, stale and initial-sample timeouts, invalid timing, callback-rate
  calculation, display formatting, sensor start/callback/stop order, callback
  identity during cleanup, startup-failure cleanup, and suppression of a late
  callback after stop. Added checks cover callback interval/open-gap
  calculations, compact timing formatting, constant-memory per-stream extrema,
  the initial/open callback gap, and rejection of backwards callback time
  without corrupting the last valid statistics. Presentation tests verify
  that the timing fault is latched and takes precedence, the monitoring banner
  requires both streams, a new session resets statistics, counters saturate,
  and worst-case timing text remains a fixed maximum length.
- Seven added checks verify the exact 150,000 ms page-bright request, success and
  failure return handling, exception containment, cleanup after request failure,
  a single explicit reset, idempotent repeated cleanup, and suppression of a
  request after cleanup. They also verify that early cleanup resets an
  initialized display lifetime even before a request. Injected fake display
  functions keep these host tests independent of Zepp firmware.

## Tool/security observations

- The app declares only the Zepp accelerometer and gyroscope permissions. It
  declares no background-service, storage, BLE, network, or notification
  permission.
- The page requests one finite 150-second screen-lighting interval through
  `@zos/display`, then explicitly resets it on normal page destruction and on
  a caught synchronous page-build failure. The display-lifetime adapter
  contains API failures and makes cleanup idempotent. This changes neither the
  permission set nor the foreground-only acquisition boundary.
- Timing observation uses a fixed set of scalar fields per stream and retains
  no callback history, paired samples, raw-motion log, or algorithm input
  buffer.
- There are no delivered npm runtime dependencies; npm packages are used by
  the development build only.
- The clean development dependency install reported 31 known transitive
  vulnerabilities: 3 low, 7 moderate, 19 high, and 2 critical.
- Zeus CLI 1.9.3 still needs the checked compatibility link to its bundled
  `zeppos-app-utils`. Zeus and its dependency tree require NPS/security
  evaluation before build output is accepted as controlled lifecycle evidence.

- background or continuous monitoring;
- exact or guaranteed sample frequency;
- long-duration reliability and battery consumption;
- firmware enforcement of the page-bright request and return to the user's
  normal display policy after cleanup;
- motion-data storage, export, or phone communication;
- algorithm-driven detection or alerting; and
- operation on a physical watch until the pending protocol is run.
